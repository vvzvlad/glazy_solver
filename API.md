# API документация Glazy Solver

## Базовая информация

API-сервер доступен по адресу `http://localhost:5000/api` при локальном запуске
(`python api_server.py`). Тот же процесс отдаёт статические файлы веб-UI из
директории `UI/` по корневому пути `/`.

Все API-методы принимают и возвращают данные в формате JSON.

## Движки решателя

Рецепт можно считать одним из двух движков, выбор — параметром `solver` в
`POST /api/solve`.

- **`iterative`** (по умолчанию, `solver_iterative.py`) — итеративный решатель
  по приоритетам материалов (`database/priorities.json`). Стартует с наиболее
  приоритетных материалов, на каждой итерации добавляет материал, лучше всех
  закрывающий самый дефицитный оксид, и пересчитывает NNLS. **Детерминирован**:
  один и тот же запрос всегда даёт один и тот же ответ. На эталонных рецептах
  (см. `compare_solvers.py`) точнее воспроизводит исходный набор материалов и
  обходится меньшим их числом.
- **`classic`** (`solver_classic.py`) — старое проверенное ядро. Решает NNLS на
  полном наборе материалов инвентаря, а затем перебирает случайные подмножества
  материалов, отбирая варианты с приемлемой ошибкой. Из-за случайного перебора
  **недетерминирован**: одинаковые запросы могут дать разные рецепты.

Итеративный движок выбран дефолтным по замерам на 11 эталонных рецептах
(`compare_solvers.py`, сводка в `REFACTORING.md`, раздел 8): медиана суммарной
ошибки 0.0020 против 0.0030, время решения втрое меньше, точный исходный состав
восстановлен в 10 рецептах из 11 против 2 у классики.

Формат ответа у обоих движков одинаковый: у `iterative` он дополнен полями
`objective_error`, `unlisted_weight` и `unity_scale`.

В веб-UI движок выбирается радиокнопками в карточке «Настройки расчета»;
выбор запоминается в `localStorage` браузера.

## Endpoints

### Расчет рецепта глазури

**Endpoint:** `POST /api/solve`

**Описание:** Подбирает рецепты по заданной UMF-формуле из доступных материалов.

**Input:**
```json
{
  "umf": {
    "SiO2": 4,
    "Al2O3": 1,
    "Na2O": 0.5,
    "K2O": 0.5
  },
  "max_solutions": 3,
  "min_materials": true,
  "error_tolerance": 0.01,
  "solver": "iterative",
  "inventory": ["Нефелин-сиенит VR13", "Каолин КЖФ-1"]
}
```

**Параметры:**
- `umf` (обязательный): UMF формула глазури в виде словаря оксид:значение
- `max_solutions` (опциональный, по умолчанию 3): максимальное количество возвращаемых решений
- `min_materials` (опциональный, по умолчанию true): предпочитать решения с меньшим количеством материалов; используется только движком `classic`, движок `iterative` параметр игнорирует
- `error_tolerance` (опциональный, по умолчанию 0.01): допустимое увеличение ошибки для решений с меньшим числом материалов; используется только движком `classic`, движок `iterative` параметр игнорирует
- `solver` (опциональный, по умолчанию `"iterative"`): движок расчёта, `"iterative"` или `"classic"`. Неизвестное значение → `400 unknown_solver`
- `penalize_unlisted` (опциональный, по умолчанию 1.0): насколько сильно оксид, не указанный в `umf`, прижимается к нулю. `1.0`/`true` — «не указан значит должен быть нулём», `0.0`/`false` — «всё равно», между ними мягкий вес. Используется только движком `iterative`
- `inventory` (опциональный): список имён доступных материалов. Если не передан, берутся материалы с флагом `inInventory: true` из базы

**Output:** массив решений, лучшее — первым.
```json
[
  {
    "recipe": {
      "Нефелин-сиенит VR13": 29.78,
      "Каолин КЖФ-1": 22.7,
      "Улексит (Химпэк)": 28.26,
      "Древесная зола": 19.26
    },
    "error": 0.0,
    "materials_count": 4,
    "target_composition": {
      "SiO2": 4,
      "Al2O3": 1,
      "Na2O": 0.5,
      "K2O": 0.5
    },
    "actual_composition": {
      "SiO2": 4.0,
      "Al2O3": 1.0,
      "Na2O": 0.5,
      "K2O": 0.5,
      "CaO": 1.1751,
      "B2O3": 1.0508,
      "MgO": 0.3452,
      "P2O5": 0.1294,
      "Fe2O3": 0.0812,
      "SrO": 0.0203,
      "TiO2": 0.0076
    },
    "recipe_umf": {
      "SiO2": 4.0,
      "Al2O3": 1.0,
      "Na2O": 0.5,
      "K2O": 0.5,
      "CaO": 1.1751,
      "B2O3": 1.0508,
      "MgO": 0.3452,
      "P2O5": 0.1294,
      "Fe2O3": 0.0812,
      "SrO": 0.0203,
      "TiO2": 0.0076
    },
    "weight_composition": {
      "SiO2": 34.36,
      "Al2O3": 14.57,
      "Na2O": 4.43,
      "K2O": 6.73,
      "CaO": 9.42,
      "B2O3": 10.46,
      "MgO": 1.99,
      "P2O5": 2.63,
      "Fe2O3": 1.83,
      "SrO": 0.28,
      "TiO2": 0.09
    }
  }
]
```

**Поля решения:**
- `recipe`: рецепт в виде словаря материал:весовой процент, сумма — 100
- `error`: метрика расхождения полученной UMF с целевой (меньше — лучше)
- `materials_count`: количество материалов в рецепте
- `target_composition`: целевая UMF. У движка `iterative` это очищенная целевая формула, с которой он реально работал: оксиды с неизвестным именем или некорректным значением из неё выброшены
- `actual_composition`: фактическая UMF рецепта. Содержит и оксиды, которых не было в целевой формуле — они приходят с материалами
- `recipe_umf`: копия `actual_composition`, отдельным полем для удобства фронтенда
- `weight_composition`: фактический оксидный состав рецепта в весовых процентах. Сумма меньше 100: в формулах материалов не учитываются летучие компоненты (CO2, вода)

Движок `iterative` (дефолтный) добавляет к каждому решению ещё три поля:
- `objective_error`: то, что реально минимизировал поиск — `error` плюс штраф за неуказанные оксиды
- `unlisted_weight`: применённый `penalize_unlisted`
- `unity_scale`: во сколько раз UMF рецепта пришлось пересчитать на базис целевой формулы

**Пример запроса с cURL (движок по умолчанию, `iterative`):**
```bash
curl -X POST http://localhost:5000/api/solve \
  -H "Content-Type: application/json" \
  -d '{"umf": {"SiO2": 4, "Al2O3": 1, "Na2O": 0.5, "K2O": 0.5}}'
```

**Пример запроса с итеративным движком и явным инвентарём:**
```bash
curl -X POST http://localhost:5000/api/solve \
  -H "Content-Type: application/json" \
  -d '{"umf": {"SiO2": 4, "Al2O3": 1, "Na2O": 0.5, "K2O": 0.5}, "solver": "iterative", "max_solutions": 2, "inventory": ["Нефелин-сиенит VR13", "Каолин КЖФ-1", "Кварцевая мука Кварцверке W12"]}'
```

**Пример запроса со старым классическим движком:**
```bash
curl -X POST http://localhost:5000/api/solve \
  -H "Content-Type: application/json" \
  -d '{"umf": {"SiO2": 4, "Al2O3": 1, "Na2O": 0.5, "K2O": 0.5}, "solver": "classic", "min_materials": true}'
```

Конкретные рецепты в ответе движка `classic` от запуска к запуску отличаются —
поиск идёт по случайным подмножествам материалов. Движок `iterative` (дефолтный)
на одинаковый запрос всегда отвечает одинаково.

### Список материалов

**Endpoint:** `GET /api/materials`

**Описание:** Возвращает материалы из базы `database/materials.json` с
проставленным приоритетом из `database/priorities.json`.

**Параметры запроса:**
- `inventory_only` (опциональный, по умолчанию `false`): если `true`, возвращаются только материалы с флагом `inInventory: true`

**Output:**
```json
[
  {
    "name": "Нефелин-сиенит VR13",
    "formula": {
      "SiO2": 62.93,
      "Al2O3": 20.33,
      "Na2O": 7.09,
      "K2O": 7.57
    },
    "inInventory": true,
    "priority": 2,
    "description": null,
    "id": 216,
    "isPublic": true,
    "userId": "4f493955-a716-44d4-8d6b-efe4a2f02b7a"
  }
]
```

Значимые для расчёта поля:
- `name`: имя материала, оно же ключ в рецепте
- `formula`: оксидный состав материала в весовых процентах
- `inInventory`: признак наличия материала в инвентаре по умолчанию
- `priority`: приоритет материала (меньше число — выше приоритет). Материалам, которых нет в `priorities.json`, проставляется 100

**Пример запроса с cURL:**
```bash
curl -X GET "http://localhost:5000/api/materials?inventory_only=true"
```

### Молярные массы оксидов

**Endpoint:** `GET /api/molar_masses`

**Описание:** Возвращает содержимое `database/molar_masses.json` — словарь
оксид:молярная масса, тот же, что используется при конвертации UMF↔веса.

**Output:**
```json
{
  "SiO2": 60.08,
  "Al2O3": 101.96,
  "Na2O": 61.98,
  "K2O": 94.2
}
```

**Пример запроса с cURL:**
```bash
curl -X GET http://localhost:5000/api/molar_masses
```

Если файл `database/molar_masses.json` отсутствует, возвращается `404` с кодом
ошибки `file_not_found`.

### Конвертация UMF в весовые проценты

**Endpoint:** `POST /api/umf_to_weights`

**Описание:** Преобразует UMF-формулу в весовые проценты.

**Input:**
```json
{
  "umf": {
    "SiO2": 4,
    "Al2O3": 1,
    "Na2O": 0.5,
    "K2O": 0.5
  }
}
```

**Output:**
```json
{
  "weights": {
    "SiO2": 57.17,
    "Al2O3": 24.25,
    "Na2O": 7.37,
    "K2O": 11.2
  }
}
```

**Пример запроса с cURL:**
```bash
curl -X POST http://localhost:5000/api/umf_to_weights \
  -H "Content-Type: application/json" \
  -d '{"umf": {"SiO2": 4, "Al2O3": 1, "Na2O": 0.5, "K2O": 0.5}}'
```

### Конвертация весовых процентов в UMF

**Endpoint:** `POST /api/weights_to_umf`

**Описание:** Преобразует весовые проценты оксидов в UMF-формулу.

**Input:**
```json
{
  "weights": {
    "SiO2": 65.2,
    "Al2O3": 18.1,
    "Na2O": 8.4,
    "K2O": 8.3
  }
}
```

**Output:**
```json
{
  "umf": {
    "SiO2": 4.853,
    "Al2O3": 0.794,
    "Na2O": 0.606,
    "K2O": 0.394
  }
}
```

**Пример запроса с cURL:**
```bash
curl -X POST http://localhost:5000/api/weights_to_umf \
  -H "Content-Type: application/json" \
  -d '{"weights": {"SiO2": 65.2, "Al2O3": 18.1, "Na2O": 8.4, "K2O": 8.3}}'
```

## Коды ошибок

### HTTP Status Codes

- `200 OK` - Запрос выполнен успешно
- `400 Bad Request` - Отсутствуют обязательные параметры или неправильный формат запроса 
- `404 Not Found` - Запрашиваемый ресурс не найден
- `500 Internal Server Error` - Ошибка при выполнении запроса на сервере

### Error Response Format

```json
{
  "error": "error_code",
  "message": "Detailed error message"
}
```

Возможные значения `error_code`:
- `missing_umf` (400) - Отсутствует обязательный параметр umf
- `missing_weights` (400) - Отсутствует обязательный параметр weights
- `unknown_solver` (400) - В параметре `solver` передано значение, отличное от `classic` и `iterative`
- `file_not_found` (404) - Файл базы данных не найден
- `not_found` (404) - Запрашиваемый API-эндпоинт не существует
- `calculation_error` (500) - Ошибка при расчете рецепта
- `server_error` (500) - Внутренняя ошибка сервера

**Пример ошибки:**
```bash
curl -X POST http://localhost:5000/api/solve \
  -H "Content-Type: application/json" \
  -d '{"umf": {"SiO2": 4}, "solver": "magic"}'
```

```json
{
  "error": "unknown_solver",
  "message": "unknown solver 'magic', expected one of: classic, iterative"
}
```
